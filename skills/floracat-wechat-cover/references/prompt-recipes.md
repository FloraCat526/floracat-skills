# 两份封面 prompt

先确定实际文字和每张图片的角色，再组装 prompt。文件是可复用记录，真正调用时仍要用工具的图片输入机制传入参考。

## 共用字段

```text
用途：微信公众号封面。
模式：{scene / title / architecture}。
文章主题与内容依据：{从真实输入提炼，含来源}。
人物身份参考：{xiaoyuan-primary.png；如需 Q 版补充 xiaoyuan-chibi.png}。
风格参考：{当前选定配色/构图文件}。
角色约束：同一小沅 IP，蓝色长发、棕色大眼、白色蓝猫 T 恤；保持身份。
配色：{blue-purple / pale-yellow 及相应背景、文字、强调色}。
必须准确的文字：{逐字列出，区分标题、副标题、模块名；无字需求写无文字}。
内容约束：不植入参考图的示例标题、产品数量、指标或模块；不编造文章外事实。
```

## 大图补充

```text
画面：横版约 2.13:1，单独一张主封面，不在这张图里绘制右侧小封面。
构图：{按当前模式写人物位置、文字区、具体动作/道具或架构关系}。
可读性：中文准确，标题清晰，重要文字、脸部、手部和关键图形距边缘留出约 5% 安全边距。
```

- scene：写出“人物—动作—对象—空间”的关系；标题按输入决定，避免把全文画成仪表盘。
- title：写出语义分行、重点词配色和左文右人构图。
- architecture：列出保留的节点与每条箭头的真实起终点、分组和循环。不要把原图当成仅提供色彩的图片。

## 小图补充

```text
画面：1:1 方形，独立缩略封面，主题和配色与已验收的大图一致。
额外参考：{已验收大图；仅用于视觉一致性，不能机械裁切}。
短主题原文：{brief 中确定的小图文字}。
构图：{人物近景、核心道具/结构、标题分行和安全边距}。
信息简化：{明确省去哪些背景、次级文字或支线；保留什么核心含义}。
可读性：在约 160×160 显示时人物、主题和主要道具仍能识别。
```

标题若不能在缩略尺寸下清晰显示，优先提炼准确主题或减少辅助信息。用户要求逐字标题时尊重原文；不要在不说明的情况下改写观点。

## 迭代

记录缺陷后只改与缺陷相关的部分：错字用准确文字约束；人物漂移重新绑定原始 IP；箭头错误回到真实架构关系；拥挤则调整文字区/模块数量。更新 prompt 后再生成，保留上一版文件。不要靠反复随机生成掩盖没有明确检查标准的问题。
