# 左大右小的输出与拼接

## 默认比例

图八原文件为 2167×726，左右画面边界约在 x=1474；右侧约 693×726，接近方形，左侧宽高比约 2.03。以左右宽度比较，约为 2.13:1。为了交付稳定的**等高横版主图 + 正方形缩略图**，默认将左右宽度比例归纳为 2.13:1：

| 文件 | 尺寸 | 布局 |
|---|---|---|
| `cover-main.png` | 2130×1000 | 左侧主封面，约 2.13:1 |
| `cover-thumbnail.png` | 1000×1000 | 右侧方形缩略封面 |
| `cover-combined.png` | 3130×1000 | 左图后接右图，同高，无缝，无外框 |

这是对用户参考图布局的规范化，**不是微信公众号官方上传规格**。明确要求其他尺寸/比例时以用户要求为准；例如用户要求 2.35:1 主图，可用 `--main-aspect 2.35`，不要暗中更换默认。

拼接缝左右各自完整成图，不跨缝放标题、人物、节点或箭头。右图是独立排版的封面，不能以从左图任意截取一个方块代替。

## 执行

脚本只做格式转换、等比尺寸规范和左右拼接，不调用生成 API。

```bash
python3 "{baseDir}/scripts/compose_covers.py" \
  --main "/path/to/generated-main.png" \
  --thumbnail "/path/to/generated-thumbnail.png" \
  --output-dir "/path/to/outputs/wechat-cover/topic" \
  --background "#FFF8E9"
```

蓝紫补边可用 `#EAF6FF`。需要 Python 3 与 Pillow；在实际解释器缺依赖时明确说明。不要硬编码作者机器的解释器路径，已有宿主依赖运行时可直接使用。

默认 `--fit contain` 等比完整保留，不拉伸、不裁切文字和人物。若原始图片比例已匹配，直接等比缩放；比例不同会产生与配色一致的补边。补边明显影响成品时优先重新调整生成构图。

`--fit cover` 会等比裁切，只在用户接受裁切且检查过文字、人物、箭头安全时使用。已有输出不会默认覆盖；优先使用新的版本目录，明确替换已生成成品时才用 `--overwrite`。

脚本输出三个真正的 PNG 及 `layout.json`，记录尺寸和拟合几何。查看这些最终文件，不能仅凭命令退出成功宣称视觉验收通过。

## 交付

在当前宿主支持的图片展示方式中展示组合图。保留两个独立文件，便于后续使用。给出可打开的路径；brief 和 prompt 留在同一输出目录，便于修改与复现。用户只要封面，不追加发布、发送或安装操作。
