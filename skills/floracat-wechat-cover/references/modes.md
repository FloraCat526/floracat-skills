# 三种封面模式

只读取当前模式的部分。配色统一按 visual-system.md 选择，不因模式而限制颜色。

## scene：根据文章生成场景化封面

参考图六、七。把文章的核心行为画成一个具体场景，而不是把摘要贴在背景上。

1. 读文章实际内容，选一个最能说明价值的行为：记录/复盘、使用产品、比较方案、观察结果或安排工作。
2. 定义小沅正在做什么、操作对象是什么、空间如何帮助读者理解。用少数道具表达文章，避免堆砌泛科技图标。
3. 把人物放入明亮的办公室、书桌、咖啡馆等合理空间；可按内容换空间，不固定套咖啡馆。人物与屏幕/手机/笔记有可见互动，保持同一 IP。
4. 若涉及产品界面，采用用户提供的真实界面或明确的示意界面；不能编造功能、数字成绩、用户反馈或不存在的品牌。复杂正文用图形和短标签表达，不生成大段难读的小字。
5. 标题可简短置于留白区或自然融入场景；用户要求无字时不加大标题。人物表情与内容含义一致。

**大图**：环境 + 人物 + 操作对象形成叙事，为标题留出空间。角色可在左或右，以实际场景为准。

**小图**：重新构图为人物近景 + 核心道具 + 短主题，不把整间办公室缩进方形。角色脸、道具和主题在缩略尺寸仍能识别。

蓝紫版可用日光、冰蓝屏幕和浅紫环境光；浅黄版可用暖日光、奶油色空间和暖橙强调。避免改变人物发色来配色。

## title：根据标题生成标题化封面

参考图三。标题是主视觉，小沅负责指向、解释或呼应主题。

1. 使用用户给定标题的原文，先分出主题名、主结论与强调词；没有事实来源时不自行增加数字、排名或夸张结论。
2. 默认大图左侧为标题、右侧为人物；在不改变原意的前提下按语义分行，保持准确标点与英文专名。长标题优先调整分行和文字区，不靠极小字体容纳。
3. 深蓝为主体字色，浅黄版可用暖橙突出重点词，蓝紫版可用亮蓝/柔紫突出；清晰、粗重、少装饰。背景可加少量与题意相关的图标或卡片。
4. 对标题之外的事实、产品能力或用户体验不要补写。仅为构图而需短副标题时从已给内容提炼并记录。

**小图**：标题按方形重新分行，突出核心词和小沅近景，减少装饰。可用不改变含义的短主题；若用户要求两图相同标题，保留全文并调整排版。

## architecture：根据架构图生成架构图式封面

参考图四。先忠实于实际关系，再做封面级简化。

1. 查看用户提供的图。HTML/SVG 应实际打开或渲染核对；已有节点文字和箭头语义是内容依据。
2. 提取核心系统名、主要节点、分组、方向和循环。保留关键依赖与返回路径；不要把无方向的关联变成数据流。
3. 封面需要减负时，挑选约 3–6 个最有解释力的模块/步骤，数字只是建议。省略的支线和理由记在 brief；不可编造核心关系或把循环改成错误的单向流程。
4. 大图顶部放主题/标题，下方为模块卡片与清晰箭头。小沅在一侧做讲解手势，不挡标题、箭头或节点文字。宽度不足时先简化标签、增大卡片，避免挤压小字。
5. 技术图的中文/英文模块名需要逐字核对。若图片生成反复画错字或箭头，可保留生成的人物背景，采用可编辑文本/SVG 技术层按真实图关系排版并渲染；这是精确排版辅助，不以纯代码占位替代 IP 封面。

**小图**：系统主题 + 小沅 + 一个核心结构/少量关键模块。不得将复杂全图简单缩成不可读的方块；省略细节后仍应保持核心关系正确。

若只有题材名称而没有实际架构依据，可按用户要求画“概念示意”，并在 brief 中说明；不得称为该产品真实架构。
